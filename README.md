# 그리움과 시 — 순수 HTML 웹

오늘의 마음을 남기고, 직접 쓴 시와 보내지 않는 편지를 보관하는 순수 HTML·CSS·일반 JavaScript로 동작하는 한국어 웹앱입니다. 첫 방문에는 실제 빈 상태가 표시됩니다. 예시 회원, 공개 글, AI 생성 시, 발송·답장 기능은 없습니다.

## 실행과 배포

HTML에서 `native-bridge.js → app.js → common-account.js → pwa.js`를 일반 `defer` 스크립트로 읽습니다. 앱 상태·함수는 IIFE 안에 둡니다. React·Next.js·Vite·npm 설치·컴파일·애플리케이션 ES module 없이 실행합니다. 한눈 공통 계정 연결에만 중앙 운영 모듈을 불러옵니다.

저장소 루트에서 정적 서버를 엽니다.

```sh
python -m http.server 8080 --bind 127.0.0.1
```

브라우저에서 `http://127.0.0.1:8080/`를 엽니다. 별도 빌드 출력 디렉터리가 없으므로 **저장소 루트 자체**를 정적 호스팅 대상으로 사용합니다. `file://`의 저장·다운로드·서비스워커 동작은 브라우저마다 달라 HTTP(S)에서 사용하고 검증합니다.

GitHub Pages의 게시 소스는 **GitHub Actions**로 지정합니다. `.github/workflows/pages.yml`이 `main` 푸시 또는 수동 실행 시 검증 후 HTML·CSS·JS·manifest·아이콘만 선별 복사하여 배포합니다. npm 설치·컴파일은 없으며 README·검증 스크립트·GitHub 설정 파일은 배포 산출물에서 제외합니다. 업로드 산출물 보관 기간은 1일입니다. 모든 앱 파일, 아이콘, manifest의 시작 URL·범위, 서비스워커 등록을 `./` 경로로 지정하여 `/geurium-poetry-web/` 같은 하위 경로에서도 동작합니다. HTTPS 또는 로컬 보안 컨텍스트에서는 서비스워커를 설치하고 앱 파일을 캐시하여 오프라인 재접속을 지원합니다. 캐시 이름에 배포 경로를 포함하므로 같은 호스트의 별도 배포와 충돌하지 않습니다.

호스팅 주소를 바꾸면 브라우저 저장 공간도 달라집니다. 기존 주소에서 JSON 백업을 받은 뒤 새 주소에서 복원합니다. Android WebView와 일반 브라우저 사이에도 자동 기록 동기화가 없습니다.

| 파일 | 역할 |
| --- | --- |
| index.html | 문서 구조·접근성 기본 요소·일반 스크립트 로딩 |

| scripts/check.cjs | Node.js 기본 모듈만 사용하는 배포 파일·기록 호환성 검증 |

## 제공 기능

| 영역 | 제공 기능 |
| --- | --- |
| 오늘의 마음 | 감정 6종 중 하나 선택, 선택적인 메모, 하루 여러 번 기록 |
| 시 쓰기 | 제목·본문 직접 작성, 원작 질문 힌트 4개, 시집 색 선택, 줄바꿈 보존 |
| 편지 쓰기 | 받는 사람·제목·본문·편지지 색, 발송하지 않는 개인 편지 |
| 작성 보관 | 입력 후 약 650ms에 작성 중 글 임시 보관, 초안 저장, 글 완성, 수정 |
| 내 글 모음 | 제목·본문·받는 사람 검색, 종류 전체/시/편지와 상태 전체/완성/초안의 독립 필터 |
| 마음 달력 | 실제 기록 수, 날짜별 기록, 지난 7일의 마지막 감정, 개별 기록 삭제 |
| 글 내보내기 | 한글 TXT 파일 저장, 브라우저 인쇄·PDF 출력 기능 연결 |
| 기록 관리 | JSON 전체 백업, 검증 후 합쳐 복원, 명시적 확인 후 전체 삭제 |
| 도움말 | 저장 위치, 동기화 범위, 발송 여부, 개인정보·공용 기기 안내 |

시 작성 화면에는 수신인 항목이 없습니다. 입력한 본문은 저장할 때 `trim()`하지 않으며, 빈 줄과 마지막 줄바꿈도 유지합니다. 앱이 자동으로 시를 완성하지 않습니다. 작성 힌트는 이 앱을 위해 새로 작성한 질문입니다.

## 데이터와 호환성

- 저장 키: `geurium-records-v1`. 제품명을 바꿔도 기존 기록을 읽도록 유지합니다.
- 데이터 버전: `version: 1`.
- 저장 데이터: `moods`, `letters`, `composer`.
- 글의 종류: `kind: "letter" | "poem"`. 이전 기록이나 백업에 `kind`가 없으면 `letter`로 정규화합니다.
- 백업 식별자: `app: "geurium"`. 이전 그리움 백업과의 호환을 위해 유지합니다.
- 시의 `recipient`는 빈 문자열로 정규화합니다.
- 마음 메모 최대 2,000자, 글 제목 최대 160자, 받는 사람 최대 120자, 글 본문 최대 50,000자입니다.
- 마음과 글은 각각 최대 10,000개입니다. 실제로는 브라우저의 저장 공간 한도가 더 먼저 적용될 수 있습니다.
- JSON 백업 파일은 5MB 이하를 받습니다. 저장 전에도 같은 형식의 UTF-8 백업 크기를 검사하므로 앱이 새로 저장한 기록을 자신의 복원 기능에서 거부하지 않도록 합니다.

### 복원 규칙

1. 파일 크기·JSON 문법·앱 식별자를 확인합니다.
2. 모든 기록의 자료형·글 종류·감정·색·상태·날짜·ID·길이를 검증합니다.
3. 검증이 끝난 후 개수를 표시하고 사용자가 복원 버튼을 누르면 진행합니다.
4. 현재 기록을 유지한 채 새 기록을 추가합니다.
5. 같은 ID와 같은 내용은 중복 추가하지 않습니다.
6. 같은 ID지만 내용이 다르면 새 ID를 부여해 두 기록 모두 남깁니다. 같은 충돌 내용을 반복 복원해도 복제본이 계속 늘지 않도록 비교합니다.
7. 백업의 작성 중인 글은 이미 같은 글이 있지 않으면 초안으로 추가합니다. 현재 작성 중인 글은 유지합니다.
8. 전체 후보 데이터를 한 번에 직렬화해 저장합니다. 저장 실패 시 기존 앱 상태를 성공한 것처럼 바꾸지 않습니다.

### 데이터 손실 방지

- 쓰기가 성공한 뒤 앱 상태를 바꿉니다. 저장 공간·브라우저 권한 오류 시 성공 알림을 표시하지 않습니다.
- 기존 저장 데이터를 읽지 못하면 원본을 덮어쓰지 않고, 원본 파일을 내려받을 수 있는 복구 안내를 제공합니다.
- 작성 중 종류를 바꾸거나 다른 글을 열 때 기존 작성 내용은 필요한 경우 별도 초안으로 보존합니다.
- 다른 탭의 변경을 감지하거나 저장 직전 값이 달라졌으면 덮어쓰기를 멈춥니다. 작성 중인 글을 TXT 파일로 보관하고 새로고침하는 경로를 제공합니다. 여러 탭에서 동시에 편집하는 방식의 협업 기능은 아닙니다.
- 인쇄 후와 글 삭제·전체 삭제 시 임시 인쇄 원문을 비웁니다.

## 보관 범위와 제약

개인 기록은 현재 브라우저의 `localStorage`에 저장합니다. 시·편지·마음 기록을 서버로 보내는 요청이나 기록 분석 도구는 구현하지 않았습니다. 공통 계정 모듈의 파일 로딩·인증 상태 확인 요청은 별도로 발생합니다. 호스팅 서비스의 일반 접속 정보 처리는 별개입니다.

기기 간 자동 동기화, 별도 암호화, 비밀번호 잠금, 예약 발송, 타인의 답장, 결제, 광고, AI 생성 기능을 제공하지 않습니다. 같은 기기·브라우저를 쓰는 사람은 기록에 접근할 수 있습니다. 비공개 모드 종료·사이트 데이터 삭제·브라우저의 저장 공간 정리로 기록이 사라질 수 있어 백업 안내를 화면에 표시합니다. JSON과 TXT 파일에는 작성 내용이 그대로 들어 있습니다.

## 접근성과 화면

- 모바일 하단 탐색, 데스크톱 사이드바, 반응형 글 카드·달력.
- 본문·입력 16px 이상, 일반 라벨·저장 안내 14px 이상.
- 입력과 버튼에 한글 레이블, 감정·종류·상태 선택에 `aria-pressed` 사용.
- 키보드 포커스 표시, 본문 바로가기, native dialog 초점 처리.
- 저장 결과 `role="status"`, 오류 `role="alert"`.
- 사용자 텍스트와 백업 내용은 HTML에 넣기 전 escape합니다. 사용자 HTML을 실행하지 않습니다.
- 외부 CDN·웹폰트·사진 요청 없이 시스템 글꼴과 직접 작성한 SVG/CSS 장식을 사용합니다.

## 검증

```sh
node scripts/check.cjs
```

설치할 npm 패키지가 없습니다. 일반 스크립트 구문, 참조 파일·manifest·오프라인 캐시 파일, 이전 기록의 글 종류 호환, 시의 줄바꿈, 잘못된 데이터 거부, 백업 ID 충돌과 중복 복원을 검증합니다.

브라우저에서는 시·편지 작성, 임시 보관·완성·수정, 종류와 상태 필터의 교집합, 전체 검색, JSON 백업 왕복, 기존 기록 복원, 모바일 화면, 새로고침, 오프라인 재접속을 확인합니다. 테스트용 글이나 실제 사용자 데이터는 배포 파일에 포함하지 않습니다.

## 한눈 서비스 공통 적용 범위

| 구분 | 동작 |
| --- | --- |
| 공통 계정 | 중앙 한눈 계정의 사이트 식별자 `geuriumpoetry`와 `#siteAccountSlot`을 사용합니다. 임의의 새 회원 시스템은 만들지 않습니다. |
| 기록 보관 | 답변·시·편지·마음 기록은 로컬에 보관합니다. 한눈 계정 로그인은 기록 동기화나 온라인 백업을 의미하지 않습니다. |
| 외부 요청 | 운영 웹에서는 중앙 공통 계정 JS/CSS와 계정 상태 확인 요청이 생깁니다. 개인 기록·한눈애 초대 fragment는 인증 요청에 자동으로 포함하지 않습니다. |
| 장애·오프라인 | 공통 계정 로딩과 개인 기록 기능을 분리합니다. 중앙 모듈을 불러오지 못하면 외부 한눈 계정 웹사이트 링크를 유지합니다. 원격 계정 모듈은 오프라인 캐시에 넣지 않습니다. |
| Android·미리보기 | `appassets.androidplatform.net`, `file:`, 로컬 미리보기에서는 중앙 계정 모듈을 로드하지 않고 외부 계정 웹사이트 링크를 제공합니다. Android 번들은 자체 앱 업데이트로 갱신하므로 PWA 서비스워커도 설치하지 않습니다. |
| 광고 | 웹 AdFit 요청·운영 광고 ID·승인 없는 광고 지면을 넣지 않았습니다. `AdMobNative/1` 환경을 식별하여 웹 광고 비활성 정책을 유지합니다. 실제 네이티브 AdMob·UMP는 Android 공통 라이브러리가 처리합니다. |
| 데이터 이동 | 주소·기기·브라우저·WebView 간 자동 동기화가 없습니다. JSON 파일로 백업·복원합니다. |

계정 폴백 주소는 `https://softm-hannun-account.softm.workers.dev/account`이며 새 창에서 엽니다. 공통 계정 연결은 현재 등록된 운영 origin `https://softm.github.io`에서만 초기화합니다. 다른 도메인에 배포한다면 중앙 사이트 origin 등록과 `common-account.js`의 허용 호스트를 함께 변경해야 합니다.

### Android 연결

`native-bridge.js`는 신뢰하는 앱 asset-loader origin에서만 `HannunNative.postMessage`를 사용합니다. 메시지는 `downloadText`(텍스트 파일 저장), `share`(사용자가 누른 링크 공유), `print`(인쇄) 세 종류입니다. 일반 브라우저에서는 기존 다운로드·시스템 공유·인쇄 동작을 사용합니다. 네이티브 저장 결과는 `hannun-native-result` 이벤트로 반영하고, 파일 선택 입력은 Android의 문서 선택 창에 연결합니다.
